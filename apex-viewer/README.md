# APEX Design Explorer

A Vite + React single-page app for exploring the ~28k discovered designs. Filter
by stats, sort, and read-only inspect each design's `graph.py` / `prompt.py`.

## How it works

`all_workflows.jsonl` (one design per line, stats + code inline) is the source of
truth. `npm run export` splits it into two tiers of static files the app serves:

| File | What | When it loads |
|---|---|---|
| `public/data/designs.json` | every design's stats, no code (~6 MB, ~0.8 MB gzipped) | once, on startup |
| `public/data/code/<xx>/<sha1>.json` | one design's `graph` + `prompt` (~4 KB each) | lazily, when that row is clicked |

So the attribute table is instant and the 105 MB of code is only fetched a few KB
at a time. `public/data/` is generated, not committed.

## Develop

```bash
npm install
npm run export      # all_workflows.jsonl -> public/data/  (auto-finds ../all_workflows.jsonl)
npm run dev         # http://localhost:5173
```

If the JSONL lives elsewhere: `DESIGNS_JSONL=/path/to/all_workflows.jsonl npm run export`.
The repo's copy is produced by `unzip all_workflows.zip` at the repo root.

## Build

```bash
npm run export      # must run first — the data is baked into the build
npm run build       # -> dist/  (static; deploy anywhere)
npm run preview     # serve dist/ locally
```

## Docker

The container serves the static build with nginx on port 8080. The design data is
**baked into the image at build time** from the committed `all_workflows.zip`, so the
image is self-contained — it runs with no flags or volumes (which is what Skiff needs).

Build from the **repo root** (so the corpus zip is in the build context):

```bash
docker build -f apex-viewer/Dockerfile -t apex-viewer .
docker run --rm -p 8080:8080 apex-viewer        # -> http://localhost:8080
```

To swap data **without rebuilding**, mount a JSONL — it re-exports on startup and
overrides the baked-in data:

```bash
docker run --rm -p 8080:8080 \
  -v "$PWD/all_workflows.jsonl:/data/all_workflows.jsonl:ro" apex-viewer
```

## Deploy on Skiff

Skiff's Cloud Build builds `apex-viewer/Dockerfile` and applies the K8s manifests
generated by `.skiff/webapp.jsonnet` (already adapted for the static nginx image:
port 8080, 0.1 CPU / 256Mi, no secrets). Because the data is baked in, the pod is
self-contained — **no volumes, no flags** (k8s has no `docker run -v` host mounts).

To make it deploy:

1. Edit `skiff.json` — set `contact` and `team` (and `appName`, which becomes the
   hostname).
2. Provide the two **boilerplate** files Skiff needs (copied unchanged from your Skiff
   scaffold — they are not authored here):
   - `.skiff/util.libsonnet`
   - `.skiff/cloudbuild-deploy.yaml`
3. Make sure the Cloud Build step builds with the **repo root** as context and
   `-f apex-viewer/Dockerfile` (the image regenerates its data from `all_workflows.zip`,
   which must be in the checked-out tree — it is committed).
4. Push to the configured branch to deploy.

> Since this is a fully static site, plain static hosting (GitHub Pages, Netlify, S3 +
> CloudFront) also works — point it at `dist/` after `npm run export && npm run build`.
